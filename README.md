# 第九通路

DeepSeek Harness（DSH）的备份与恢复插件：把会话、工作区与工作区文件备份到**非系统盘**，在新客户端上用**一段提示词**恢复。

它针对的具体场景是：重装系统只格式化了 C 盘，其它盘的数据还在，但客户端和它的数据目录（默认在 C 盘用户目录下）已经没了。

## 它做什么

**备份**（在对话里发起）

- 拒绝把备份写到系统卷——否则重装系统时会连备份一起消失
- 分层选择：宿主数据（会话 / 工作区注册 / 偏好 / 技能）、工作区文件、附件
- 空间预检：预计体积 × 1.2 + 保留 5 GB，不够就拒绝
- 产物：`manifest.json`、`恢复说明.txt`、`使用说明书.txt`、`SHA256SUMS.txt`、插件包、安装包（若找到）
- 正在执行备份的那条会话不会被备份，它是工具会话

**恢复**（在新客户端的对话里发起）

- 读取清单、比对版本与会话格式代际，不兼容就停
- 逐工作区判断：旧路径仍有效就直接复用，失效才提问
- 三种去向：指定新路径、直接用备份里的副本、跳过
- 合并写入，不整体替换；当前会话被跳过，不会覆盖自己
- 恢复后生成 Word 报告（零依赖手写 OOXML，不需要 Office 库）

## 安装

> **先说明一点**：DSH 桌面版通常**不把 `dsh` 命令装进 PATH**，所以 `dsh plugin ...` 不一定可用。下面按可用程度排序，前两种不依赖命令行。

### 首选：让 agent 安装

把插件目录给 agent，说「把这个目录作为插件安装」。agent 会调用 `plugin_manager` 的 `install_bundle`，target 指向该目录的绝对路径。

这是桌面版最可靠的方式，已在本地实测通过。

### 次选：插件页面

打开 设置 → 插件，若界面提供「从本地目录/路径安装」入口，选择插件目录即可。

### 备选：命令行

需要先确保 `dsh` 命令可用（例如 `npm i -g @deepseek-ai/dsh`）：

```powershell
dsh plugin --profile <profile 名> add "<插件目录绝对路径>"
# 开发时可用链接形式，源码改动即时生效；代价是源目录不能删
dsh plugin --profile <profile 名> add "link:<本仓库路径>"
```

`dsh` 不在 PATH 时这条命令会直接报「不是内部或外部命令」，这**不是插件的问题**。

### 整合包

下载 release 里的 `第九通路-v0.1.3.zip`，解压得到 `第九通路/` 文件夹，再按上面任一方式安装。包内附 `安装说明.txt`。

### 共同要求

装完必须重启客户端，Host 半区在启动时加载。本插件零第三方运行时依赖，离线可装，不需要 `npm install`。插件本体不调用任何 shell，与 PowerShell 版本无关。

## 工具

| 工具 | 用途 |
|---|---|
| `ninth_path_status` | 数据目录、客户端版本、会话数、工作区列表 |
| `ninth_path_bind_role` | 把当前会话认定为备份/恢复工作区（只有显式调用才算） |
| `ninth_path_backup` | 执行备份，支持 `dryRun` 预检 |
| `ninth_path_restore_plan` | 读清单、判兼容、给出每个工作区的建议模式 |
| `ninth_path_restore_apply` | 执行恢复并生成 Word 报告 |

## 能恢复什么、不能恢复什么

**能**：宿主数据、工作区注册与路径、会话全文、工作区目录内的文件（若勾选）。

**不能**：工作区以外的文件、已删除的内容、插件私有数据，以及一切外部副作用（推送、安装、网络请求）。

## 已知限制

- 会话正文里的旧绝对路径不会改写，那是历史记录，不是索引
- 恢复后必须重启客户端，会话列表是启动时读取的
- 客户端装的是备份时的版本；之后被自动更新属于正常现象
- 备份目录若与工作区在同一块物理盘上，磁盘损坏会双双丢失

## 打包

```powershell
node scripts/pack.mjs
```

产物在 `dist/第九通路-v<版本>.zip`，解压即为 `第九通路/`。
